# セキュリティ強化の適用手順

このブランチ（`security-hardening`）には次の変更が入っています。

| 内容 | 場所 |
|---|---|
| 勤怠（基本チェック）を事業所から半径300m以内でのみ記録可能にする | `lib/geofence.ts`, `app/page.tsx` |
| 管理画面のパスコード（ソースに直書き）を廃止し、Supabase の管理者アカウントでログイン | `app/admin/page.tsx` |
| 一般利用では記録の修正・削除を不可にし、管理者だけが修正・削除できるようにする（RLS） | `supabase/sql/02_security_hardening.sql` |
| 修正・削除の履歴（変更前後の内容・誰が・いつ）を自動保存（削除した記録も復元可能） | 同上 |
| サーバーが受け付けた実際の時刻（`server_recorded_at`）を自動記録 | 同上 |

## 適用の順番

### 0. 事業所の座標を確認（必須）

以下を開き、ピンが事業所（会津若松市一箕町大字鶴賀船ケ森東470）の上にあるか確認してください。

https://www.google.com/maps?q=37.5282,139.9465

ずれている場合は、Google マップで事業所を長押しして正しい座標を調べ、ホスティング先（Vercel 等）の環境変数に設定します。

```
NEXT_PUBLIC_STORE_LAT=37.xxxx
NEXT_PUBLIC_STORE_LNG=139.xxxx
```

座標がずれたまま公開すると、事業所内でも「事業所の外」と判定され、勤怠を記録できなくなります。
不安な場合は、最初の数日だけ `NEXT_PUBLIC_GEOFENCE_MODE=warn` を設定してください。範囲外でも記録はでき、管理画面に「🚨事業所外」と表示されます。問題がなければこの環境変数を削除します。

### 1. 管理者アカウントを作成

Supabase ダッシュボード → Authentication → Users → **Add user** → **Create new user**
- メールアドレスとパスワードを入力し、**Auto Confirm User** にチェックを入れます。

### 2. 事前確認 SQL を実行

SQL Editor で `01_preflight_check.sql` を実行し、**結果を保存**します（スクリーンショットで可）。

### 3. 本体 SQL を実行

`02_security_hardening.sql` の中の `ここに管理者のメールアドレス` を、手順1のアドレスに書き換えてから実行します。
- 1つのトランザクションで実行されるため、エラーが出た場合は何も変更されません。
- 管理者が見つからない場合は自動で中止されます。

### 4. 動作確認（現行の画面のままで可）

- スマホで基本チェック・温度管理などを1件送信できること
- 運転日報の出発 → 帰着を記録できること

**問題が起きたら** `99_rollback.sql` を実行すると、すぐ元の状態（誰でも修正・削除可）に戻ります。

### 5. ブランチをマージして公開

`security-hardening` を `main` にマージします。公開後に確認すること:
- 管理画面 `/admin` に、手順1のメールアドレスとパスワードでログインできること
- 事業所内で基本チェックを送信でき、管理画面の「位置・送信時刻」欄に「📍事業所内」と出ること

※ 手順3と5はどちらを先にしても動作します（SQL 適用前の記録は、位置情報を特記事項に書き込む方式に自動で切り替わります）。

## 位置情報の判定ルール

| 状況 | 動作 |
|---|---|
| 事業所から300m以内（屋内の測位誤差は最大100mまで考慮） | 記録できる |
| 範囲外 | **記録できない**（距離と再試行の案内を表示） |
| 位置情報を拒否・取得できない | 記録できるが「⚠️位置確認不可」と残り、管理画面で目立つ表示になる |

位置情報を取得できない場合も記録できるようにしているのは、運用中に打刻できなくなるトラブルを避けるためです。
慣れてきたら、取得できない場合も送信不可にできます。

## 注意

- 位置情報は端末側で偽装できるため、完全な不正防止ではありません。管理画面で「位置確認不可」や「事業所外」の記録を定期的に確認してください。
- 記録の閲覧は、これまでどおりログインなしで可能です（スタッフ画面が過去の記録を参照するため）。
